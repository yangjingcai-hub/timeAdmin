# FocusTime_Admin · 专注时光管理后台

独立的 React 管理后台。「数据概览」「用户管理」「订单管理」及付费「套餐管理」读取 FocusTime_Server，其他管理页面继续使用各自的现有数据来源。

## 本地启动

Windows 当前本机可直接双击根目录的 **`启动项目.cmd`**，启动完成后会自动打开 `http://127.0.0.1:5181/login`。脚本自动查找系统或 Codex 自带的 Node.js，直接运行 Vite，不要求普通 PowerShell 能识别 `pnpm`。前端依赖已存在时不重复安装。

启动入口会检查并启动原有 PostgreSQL 数据库、构建并启动 `FocusTime_Server`，最后验证前后端连通；重复点击会复用已有服务。它沿用原数据库、管理员白名单和认证密钥，不创建替代数据库、不重置账号，也不自动执行数据库迁移。

双击 **`停止项目.cmd`** 可停止本入口启动的前后端；共享数据库保留运行。停止前会核对进程 ID、启动时间和可执行文件，避免误停其他程序。关闭启动窗口不等于停止后台服务。

本机路径配置已保存在被 Git 忽略的 `.run.local/one-click/settings.json`，包括后端目录、原数据库目录/加密密码文件、原 API 配置目录和管理员配置文件。更换目录或电脑时需相应更新这些路径；缺失时脚本会明确提示，不会改用空数据。启动状态和日志位于 `.run.local/one-click/`；后端地址沿用 `.env.local` 的 `FOCUSTIME_API_TARGET`。

也可手动启动前端：

使用 Node.js 22.13+（或较新的 LTS 版本）与 pnpm：

```sh
pnpm install
pnpm dev
```

打开终端打印的本地地址（默认 `http://localhost:5173`）。`pnpm build` 执行 TypeScript 检查并生成静态产物 `dist/`，`pnpm preview` 可预览构建结果。

## 管理员登录与数据概览

1. 在 FocusTime_Server 的运行环境中设置 `AdminOverview__UserIds__0` 为获准查看数据的现有账号 ID（GUID）。多个账号使用 `__1`、`__2` 等。启动或重启后端；未配置名单时，所有账号均无权限。无需修改数据库。
2. Vite 默认将 `/api/v1/admin/` 代理到 `http://127.0.0.1:5080`。如后端地址不同，在前端 `.env.local` 设置 `FOCUSTIME_API_TARGET` 并重启 Vite。正式部署时，通过后台站点的同源 HTTPS 反向代理转发 `/api/v1/admin/`，并将页面路由回退到 `index.html`。
3. 在 `/login` 用获授权账号的邮箱和密码登录。会话由服务器签发为 HttpOnly Cookie，有效期为 8 小时，刷新页面会重新向服务器验证会话。

右上角账号菜单提供「修改密码」和「退出登录」。密码修改调用 `POST /api/v1/admin/password`，由现有 Identity 验证当前密码并执行密码策略（8–128 位，包含字母和数字）。成功后撤销该账号的所有旧会话和密码恢复凭证，需使用新密码重新登录；退出登录只撤销当前管理员会话。

部署此功能前，在后端正常迁移流程中应用 `20261105065917_AdminPasswordSecurityAudit`。变更结果在同一事务内写入 `identity.admin_security_audit`，只记录管理员 ID、时间、操作、来源、结果及错误代码，不记录密码、哈希或令牌。

`GET /api/v1/admin/overview?days=7|30|90` 要求管理员权限。日期按北京时间计算，范围包含今天；新增会员按用户首次生效的授权计算，续费不重复计入。有效会员为已经开始、未撤销、未到期的授权用户，每人只计一次，套餐以永久会员优先、其余取到期最晚的有效授权。目前没有独立体验套餐类型。订单沿用后端状态，未支付且超时显示「已过期」。订单编号使用后端订单 ID；用户没有头像时使用默认占位。

## 真实订单管理

订单列表、统计、搜索、筛选、分页、详情、处理日志及 CSV 导出均读取 `/api/v1/admin/orders`，复用已有管理员 Cookie 和权限白名单。页面通过顶部按钮手动刷新，筛选变化时重新查询并回到第一页，每页固定 10 条。四张统计卡片可筛选全部、已支付、已退款和待处理异常订单。价格、支付和开通结果以服务器订单为准，年套餐标识与后端统一为 `annual`。

居中订单弹窗展示真实订单与已保存的处理事件，不根据当前状态补造历史事件；单独的「会员权益信息」卡片已移除。用户信息按订单的 UserId 加载，关联账号详情复用用户管理的账号、会员、设备和日志页面，在同一弹窗内切换并保留订单 Tab 与滚动位置。

四项统计由服务端计算，筛选按实际存储状态查询。支付凭证来自已保存的 PaymentReference，开发环境模拟支付明确标记。官网、后台与 Windows 客户端应使用同一 API，当前本机官网和后台均连接 `http://127.0.0.1:5082`。

订单详情顶部提供退款入口，以支付完成时间起算 72 小时（含截止时刻），超过期限自动显示灰色状态及截止时间；已退款显示实际金额和时间。弹窗默认全额，可调整金额、选择原因、填写备注，并选择是否撤销本订单权益。每笔订单支持一笔退款，提交失败后原内容重试复用操作号，后台另有订单唯一约束防重复。

退款写入 `/api/v1/admin/orders/{id}/refund`，使用真实订单、服务端时间校验和持久化回执；订单状态、处理事件、审计和可选的定向权益撤销在同一事务提交。目前仅支持开发/测试环境的 simulation 支付订单，明确记录模拟退款，不发生资金划转；尚未接入的真实支付渠道拒绝提交，不伪造退款成功。需应用 `20261108175329_OrderRefunds` 增量迁移，具体规则及渠道边界见后端 `docs/ORDER_REFUNDS.md`。

## 真实操作日志

操作日志读取 `/api/v1/admin/audit-logs` 及单条详情，服务端执行搜索、类型/结果/北京时间范围筛选和分页，每 15 秒自动刷新。汇总已有会员调整回执、人工会员审计、管理员订单重试和改密记录，排除成功预览、支付自动化及重复子审计。历史缺失的 IP 和字段级变更不推算。

新增 `admin.operation_logs` 持久化套餐修改与失败的后台管理请求。套餐前后值和成功审计与套餐更新同事务保存；失败请求只记录安全的原因代码，不保存原始请求或凭证。需应用增量迁移 `20261106171601_AdminOperationLogs`；详细口径见后端 `docs/ADMIN_OPERATION_LOGS.md`。不存在的用户禁用、系统配置等写入接口不会生成模拟日志。

## 通知中心

通知复用待处理订单筛选和 API、数据库健康检查。后端每 30 秒采集一次，数据库不可用期间观察到的监控告警在连接恢复后写入。顶部铃铛每 15 秒同步最新 3 条和未读数，通知中心按时间倒序分页读取全部历史。

- `GET /api/v1/admin/notifications` 支持 `unreadOnly`、`page`、`pageSize`，返回当前页、总数和当前管理员的未读数。
- `POST /api/v1/admin/notifications/{id}/read` 和 `POST /api/v1/admin/notifications/read-all` 使用现有管理员会话及 `X-FocusTime-Admin: 1`，返回最新 3 条和更新后的未读数。
- 部署需应用后端 `20261110131946_AdminNotifications`。通知来源、跳转标识、发生时间和处理时间保存到 `admin.notifications`。已读时间按管理员保存到 `admin.notification_reads`，与业务异常的恢复独立。

## 真实用户管理

`GET /api/v1/admin/users` 与 `GET /api/v1/admin/users/{guid}` 复用管理员认证，提供只读统计、搜索、筛选、分页和详情，不需要新增数据库字段或迁移。支持 `query`（用户 GUID 或邮箱，忽略大小写的字面量包含匹配）、`membership=all|member|nonMember`、`account=all|active|disabled|deleted|locked`、`registration=all|today|week|month|quarter`、`quick=all|members|today|inactive`、`page`、`pageSize`（最多 100）。默认按注册时间倒序及用户 ID 倒序稳定分页，所有筛选在数据库中相交执行，统计卡片始终统计全部现存账号。

日期按北京时间的自然日计算。有效会员沿用会员服务的条件：已开始、未撤销且未到期；重复授权每人只计一次，永久优先，否则选择到期最晚的有效套餐。最近登录取该账号留存登录会话的最大创建时间，不能用最近活动时间替代；没有留存会话时显示「—」。

当前账号模型只有 Identity 锁定信息：启用锁定且 `LockoutEnd=+infinity` 表示永久禁用；有限未来截止时间单独显示「暂时锁定」，不计入已停用。数据库没有注销状态字段或留存注销账号模型，`deleted` 筛选不会推测或恢复已删除记录。后续若加入账号注销机制，应在此只读查询中接入其合法留存状态。页面不再保留本地模拟账号状态修改；真实禁用/恢复接口尚未开放，菜单对应入口不可用。

## 真实用户详情

用户详情的四个子页面读取真实后台数据：基本资料复用 `/api/v1/admin/users/{id}`，账号安全与云端统计、会员来源、登录会话及审计分别读取该用户的 `/account`、`/membership`、`/sessions`、`/audit`。历史订单复用已有订单接口的 `userId` 筛选与分页，详情额外核对订单归属。切换账号会取消旧请求，失败显示错误并支持重试，不回退到模拟数据。

目标、未完成任务、登录 IP/地区、风控和密码重置完成时间当前没有可靠的服务器存储，展示「—」。完成任务只统计已同步记录中的任务快照去重数；屏蔽规则仅包含服务器保存的网站规则；最近同步取成功专注记录推送的接收时间。设备展示会话有效期状态，不推测在线状态；退出设备等写入入口未开放。审计仅展示可明确关联该用户的既有管理记录，无记录时显示空状态。只读接口口径见后端 `docs/USER_DETAILS_API.md`。调整会员功能需应用 `20261106145339_AdminMembershipAdjustments` 增量迁移，写入流程见 `docs/USER_MEMBERSHIP_ADJUSTMENTS.md`。

## 管理员调整会员

用户详情的「会员与订单 → 当前会员」提供「调整会员」，支持发放月会员（30天）、年会员（365天）、永久会员，以及撤销已核实来源的管理员赠送。服务端先生成五分钟内有效的确认方案，管理员核对前后权益后再提交；实际变更、版本、审计和防重回执同一事务保存。手动发放沿用有效期叠加规则，不生成或改变支付订单。

仅明确由本功能发放、且没有订单关联的授权可按赠送范围撤销。当前没有付费权益撤销权限与退款状态核验模型，因此含购买或未知来源权益的「撤销全部」被服务端拒绝；选择退款原因不会绕过保护或执行退款。已有签名离线授权保持原到期策略，服务端撤销后客户端需联网同步或等当前授权到期。

## 页面代码

- `src/components/layout`：管理后台的导航和顶部区域。
- `src/components/ui`：shadcn/ui 风格的卡片、按钮、表格、徽章和头像组件。
- `src/features/overview`：数据概览、统计卡、Recharts 图表和最近活动列表。
- `src/features/auth`：管理员登录页面、会话和路由保护。

时间范围支持近 7、30、90 天，趋势图支持悬停查看每日数据。「查看更多」分别跳转到订单管理、用户管理。


## 真实付费套餐管理

套餐列表读取 `GET /api/v1/admin/membership-plans`，现有编辑和确认弹窗通过 `PUT /api/v1/admin/membership-plans/{id}` 保存价格、有效期、推荐和上架状态。使用现有管理员 Cookie/白名单和 `X-FocusTime-Admin: 1` 写入头。金额转换为整数分，时间由服务器返回；保存失败保持弹窗并提示错误。

套餐 ID 为 `monthly`、`annual`、`lifetime`。更新携带 `expectedVersion`，旧版本返回冲突，需关闭弹窗并刷新列表后重试。价格与期限变化只影响新订单，不改变历史订单和已经授予的会员权益。免费体验规则区域沿用原有逻辑，本次未接入服务器。

后端需应用 `20261105143836_MembershipPlans` 迁移；数据库同时作为官网价格和新订单计价的唯一来源。当前官网 `http://127.0.0.1:5175/membership/`、后台 `http://127.0.0.1:5181/plans` 均连接 `5082`，价格调整不需要重新部署官网。实际验证见后端 `docs/MEMBERSHIP_PLANS_VALIDATION.md`。
